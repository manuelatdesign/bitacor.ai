3. Flujo de datos (ejemplo / mock)

En el cliente actual, la generación usa generateMockProposals(config) en data.ts (no llama al endpoint Gemini de server.ts).

src/data.ts

Catálogos estáticos + generador mock

  • SUGGESTIONS (Medellín, Kioto…)
  • BUDGET / PACE / categorías
  • generateMockProposals()
→ lee opciones

WizardView

Escribe en TravelConfig

  • destination, days, budget
  • interests[], pace
  • fechas/horas opcionales
→ setConfig

App.tsx (estado)

Fuente de verdad en memoria

  • config, currentStep
  • proposals[]
  • savedItinerariesList

generateItinerary()

Simula ~3.5s de “IA” y llama al mock

  • input: config
  • output: 3 GeneratedItinerary
→ setProposals

ResultView

Muestra A / B / C y detalle

  • itinerary por días
  • cafés & coworks
  • practicalTips
→ onSave

localStorage

Clave bitacor_saved_itineraries

  • persiste propuestas
  • también theme dark/light

savedItinerariesList

Lista hidratada al iniciar App

→ props

TripView

Modo “En el Viaje 📸”

  • elige itinerario guardado
  • MOCK_PHOTOS_DATABASE
  • fotos / mapa / resumen
⇄ switcher

appMode

"planner" ↔ "trip"

  • Header: Nuevo → resetAll
  • BackgroundMesh / tema

4. Vista rápida del recorrido

Usuario → wizard → mock → resultados → guardado → viaje.

5. Nota sobre Gemini

server.ts expone POST /api/generate-itinerary con Gemini, pero App.tsx hoy genera con el mock local. El flujo visual de la UI se alimenta de data.ts + estado en App + localStorage.

Archivo generado solo para revisión visual · no forma parte del runtime de la app.
